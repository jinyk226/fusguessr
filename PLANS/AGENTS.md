# Plan Tracking Guidelines

## Plan Structure
Each plan must be tracked in a folder named:
(YYYY-MM-DD)-PLAN_NAME

Folder contents:
- PLAN.md: High-level overview of the plan
- PROGRESS.md: Tracking of implementation progress
- SUMMARY.md: Final summary after completion

## Plan Lifecycle
1. Create plan folder with PLAN.md
2. Update PROGRESS.md with implementation steps
3. Maintain PROGRESS.md with commit references
4. Create SUMMARY.md when plan is complete
5. Archive completed plans

## Plan Documentation
- PLAN.md should include:
  - Objective
  - Scope
  - Success criteria
  - Estimated effort
  - Dependencies

- PROGRESS.md should include:
  - Implementation status
  - Completed tasks
  - Outstanding issues
  - Next steps

- SUMMARY.md should include:
  - Final outcome
  - Lessons learned
  - Implementation details
  - Post-mortem analysis
